# 기획 문서와 모바일 서비스 화면 확인 기록

확인일: 2026-09-30 · 조사·기획 초안 기준일: 2026-09-29

## 이번에 확인한 범위

- 사업기획 정본, 고객 시나리오, 결정 기록, 시각 기획서의 방향을 교차 검토했다. 초기 수익 검증 범위를 상담·작업·상품 구매·클래스 매칭으로 맞췄다.
- 변경 전 기획서의 개요·아이템·고객 여정·검증 메뉴를 각각 320px, 390px, 480px에서 열어 가로 넘침이 없는지 확인했다. 당시에는 1280px 창에서도 문서 폭을 480px로 제한했으나, 아래 PC 문서 전환에서 이 제한을 제거했다.
- 세 아이템 전환과 일곱 고객 여정의 제목·내용·단계 변경을 확인했다.
- 수익 계산에 미성사 요청에서도 발생하는 사전 상담·견적 조율 비용을 추가했다. 거래액, 플랫폼 매출, 변동비, 고정비 차감 전 잔액을 분리했다.
- 설명용 기본값에서 완료 6건, 거래액 300,000원, 매출 30,000원, 변동비 38,000원, 고정비 차감 전 잔액 -8,000원을 확인했다. 이는 실제 사업 실적이나 예상 매출이 아니다.
- 사전 운영비를 0원으로 바꾸면 잔액 12,000원, 그 상태에서 완료 전환율을 0%로 바꾸면 -6,000원이 되는지 확인했다. 비율 101% 입력은 오류 안내로 처리한다.
- 서비스 시안의 세 문제 × 세 도움 방식 조합 9개, 목표 변경, 요청서 미리보기·닫기, 검토 질문, 오늘·내 정원·가이드 이동, 관찰 예시 반응을 확인했다.
- 서비스 시안도 320px, 390px, 480px와 넓은 창에서 모바일 폭과 가로 넘침을 확인했다. 390px 화면을 직접 살펴보았다.
- 확인 시 브라우저 콘솔 경고·오류는 없었다. JavaScript 구문과 문서의 로컬 링크 대상을 확인했다.

## 해석의 한계

브라우저에서 기획 문서와 샘플 상호작용이 작동하는지 확인한 기록이다. 실제 휴대폰 기종별 사용성 시험, 접근성 전수 검사, 사용자 20명 실험, 사진 인식·식물 진단 성능 평가를 완료했다는 뜻은 아니다.

실제 고객 모집, 인터뷰, 전문가 계약, 결제, 상담, 키트 판매, 클래스 운영은 아직 수행하지 않았다. 수요·수익성·사업지원 적격 여부는 검증되지 않았다.

정부지원 후보는 2026년 공식 공고의 확인 범위를 기록했다. 현재 접수 중인 사업 목록이나 2027년 일정으로 사용하지 않는다. 자세한 근거와 미확정 조건은 [조사·검증 문서](research-and-validation.md)에 있다.

## 사용과 수정

- `index.html`과 `assets/planning.css`, `assets/planning.js`가 시각 기획서다.
- `assets/concept.fragment.html`은 서비스 시안의 편집 원본이고 `concept.html`은 단독으로 열 수 있는 내보내기 파일이다. `python3 scripts/export-concept.py`로 원본 변경을 내보내기 파일에 반영한다.
- 개인정보를 저장하거나 외부로 사진·요청을 전송하는 기능은 없다. 선택과 입력은 화면을 다시 열면 초기화된다.
- GitHub 저장소 반영과 공개 웹사이트 배포는 별개다. 이번 산출물은 비공개 저장소와 로컬 브라우저용 문서다.


## 페르소나 검토 후 추가 확인 — 2026-09-30

- [사용성 검토](usability-review.md)의 8개 가상 페르소나를 기준으로 실제 시안의 막힘을 브라우저에서 재현했다. 실제 사람의 사용자 조사나 통계적 성공률이 아니다.
- 3개 관심사 × 3개 목표 × 3개 도움 방식의 27가지 조합에서 목표별 안내와 열린 요청서의 대상·목표·방식 표현이 일치하는지 확인했다.
- 아이템 왕복 시 목표·예산·방식 유지, 열린 요청서의 조건 갱신, 명시적인 수형 가이드 진입, 목표 변경 후 이전 사진 안내 제거를 확인했다.
- 스킨답서스 카드의 대상 연결, 메뉴 이동 후 제목 위치·초점, 요청서 제목 초점, 모름 선택의 관찰 안내 노출을 확인했다.
- 320px, 390px, 480px의 오늘·내 정원·찾기·꾸미기·가이드 화면에서 가로 넘침을 확인했다. 좁았던 하단 ‘오늘’ 버튼을 넓힌 후 표시된 버튼·선택 입력의 크기가 최소 약 44×44 CSS px인지 확인했다. 이는 접근성 전체 인증이 아니다.
- 사용성 보고서의 8개 펼침 항목과 같은 세 가지 폭을 확인했다. 검토 시 콘솔 경고·오류는 없었다.
- 원본과 내보내기 파일의 차이가 생기지 않도록 내보내기 도구를 추가했다. 이전 파일에서 일부 스타일이 다르게 반영된 점도 원본 기준으로 동기화했다.


## 초보자 흐름 보완과 인앱 브라우저 재검토 2026년 9월 30일

### 이번 작업의 기준

사용자가 선택한 첫 검토는 초보 지인이 모바일 시안에서 이름 모를 식물을 등록하고, 모름 상태의 관찰 안내를 찾고, 첫 관찰을 남기는 과업이다. 실제 모집 인원·일정은 미정이며 비용 없이 진행할 계획이다. 아래 결과는 가상 페르소나를 적용한 내부 검토로, 실제 지인 조사나 서비스 운영 실적이 아니다.

### 확인한 동작

- Codex **인앱 브라우저**에서 편집 원본을 내보낸 `concept.html`을 열고 확인했다.
- 등록 취소는 식물을 추가하지 않는다. 이름·놓인 곳을 비워도 등록할 수 있고 재배 방식의 기본값은 모름이다. 등록 버튼과 입력란의 Enter로 다음 관찰 화면에 진입했다.
- 일반 흙 화분·수경재배·테라리움·팔루다리움·재배 방식 모름의 안내를 구분했다. 흙 화분을 선택한 경우에만 흙 촉감을 살펴보는 안내가 나타났다.
- 모름으로 첫 관찰을 남기고 같은 식물의 이력에서 확인했다. 관찰을 물주기 작업으로 바꾸지 않으며, 작성자 ‘나’와 시각을 표시한다.
- 기록 수정은 기존 기록 한 개를 갱신했다. 수정 취소는 원래 값을 유지했다. 관찰 취소는 유효 관찰 수에서 제외하고, 취소 되돌리기로 같은 기록을 복원했다.
- 서로 같은 별명을 가진 식물 두 개를 다른 위치·재배 방식으로 등록했다. 각 식물의 관찰과 요청 조건이 구분되고, 이전 식물로 돌아왔을 때 그 식물의 선택이 유지됐다.
- 메뉴를 왕복해도 임시 등록·관찰이 유지됐다. 새로고침 후에는 초기 화면으로 돌아갔다. 화면에서 이 제한을 사전에 안내한다.
- 이름 80자·장소 100자와 HTML 형태의 메모를 넣어 좁은 화면의 줄바꿈과 일반 텍스트 표시를 확인했다. 이 입력은 가상 테스트 자료다.
- **3개 관심사 × 3개 목표 × 3개 도움 방식, 27조합**에서 선택한 목표·방식과 요청서가 일치했다.
- 분갈이 가이드와 수형 가이드의 목표 진입, 관심사 왕복 시 예산 유지, 열린 요청서의 조건 갱신, 목표 변경 후 이전 사진 안내 제거를 확인했다.
- 오늘·내 정원·찾기·꾸미기·가이드의 네 화면을 **320·390·480·1280px** 창에서 확인했다. 총 16가지 화면/폭 조합에서 가로 넘침이 없었고 내용 폭은 최대 480px였다. 표시된 버튼·선택 입력·일반 입력은 약 44×44 CSS px 이상이었다.

### 검토 중 발견해 수정하고 재확인한 문제

1. 내보낸 시안의 프레임 제한 때문에 등록 폼의 기본 제출이 실행되지 않았다. 버튼 클릭과 입력 Enter를 화면 안의 등록 처리에 연결했다. 폼 제출이나 외부 전송 권한은 추가하지 않았다.
2. 열린 요청서로 돌아올 때 수정·취소 전 관찰이 남았다. 돌아온 시점의 유효 관찰로 요약을 갱신하도록 바꾸고 재현 과업을 다시 확인했다.
3. 식물이 바뀌어도 이전 식물의 최근 변화·시기가 붙었다. 식물과 관심사별로 조건을 구분하고 같은 별명 두 개로 재확인했다.
4. 신규 식물의 최근 변화가 ‘한쪽으로 많이 퍼졌어요’로 미리 선택됐다. ‘아직 확인하지 않았어요’를 기본으로 바꿨다.

### 문서에 포함한 화면

390×844px 인앱 브라우저에서 가상의 ‘선물 받은 초록이’를 사용해 등록, 모름 관찰 안내, 첫 기록, 도움 요청서의 네 화면을 캡처했다. 파일은 `docs/screenshots/`에 있으며 [서비스 안내 정본](service-guide.md)과 [서비스 안내서](../service-guide.html)에 설명과 함께 삽입했다.

### 남은 검토

실제 사람의 이해·과업 수행, 휴대폰 실기기, 스크린리더 전수 검토는 아직 실시하지 않았다. 기록은 현재 열린 시안 안의 임시 상태이며 가족 동기화·장기 저장·사진 인식·전문 상담·상품 비교·결제는 검증 대상에 포함되지 않는다. 등록한 재배 방식을 나중에 수정하거나 식물 자체를 삭제하는 흐름도 이번 시안에는 없다. 용기별 안내는 기본 관찰 시안으로, 구성별 전문 관리 가이드가 아니다.

변경 전 서비스 안내 페이지는 320·390·480·1280px에서 가로 넘침 없이 최대 480px를 유지했고, 네 서비스 펼침 항목과 네 캡처 파일(각 390×844px)의 로딩을 확인했다. 인앱 브라우저의 시안·안내서 콘솔에 오류·경고가 없었다. JavaScript 구문, 문서 로컬 링크, 원본과 내보내기 일치를 확인했다.

갱신한 사용성 보고서의 10개 펼침 항목과 320·390·480·1280px 레이아웃을 인앱 브라우저에서 확인했다. 사업기획서의 초보자 여정·첫 검토 우선순위와 서비스 안내 링크도 확인했다.


## 2026-09-30 — 내부 문서를 PC 열람 기준으로 정정

사용자 정정에 따라 사업 기획서(`index.html`), 서비스 안내서(`service-guide.html`), 페르소나 보고서(`usability.html`)는 PC 문서로 구성했다. 모바일 전용은 실제 서비스 시안(`concept.html`)에만 적용한다. 이전 480px 문서 검증은 변경 전 기록이다.

- PC 문서는 최대 1320px로 펼치고 960px 이상에서 왼쪽 목차와 본문을 나란히 배치한다. 좁은 창에서는 세로로 읽는다.
- 사업 기획서의 4개 메뉴를 390·768·1024·1440px에서 각각 확인했다. 16개 조합에서 메뉴가 해당 패널을 표시하고 가로 넘침이 없었다. 아이템 선택과 초보자 고객 여정 전환도 확인했다.
- 안내서와 페르소나 보고서도 같은 4개 폭에서 확인했다. 8개 조합에서 가로 넘침이 없었으며 PC에서 캡처와 과업은 2열로 표시됐다.
- 안내서의 화면 캡처 목차 이동, 캡처 4장의 로딩(각 390×844px), 보고서의 가상 과업 10개 펼침을 확인했다.
- 키보드 본문 바로가기로 이동해도 선택한 아이템 패널과 주소 `#ideas`를 유지하고 본문에 초점이 가는 것을 확인했다.
- 1440px 창에서 서비스 시안 iframe은 480px였고 가로 넘침이 없었다. 이번 변경은 내부 문서 레이아웃에 한정했으며 서비스 시안 파일은 수정하지 않았다.

## 2026-09-30 — 신품·중고 구매비용 비교 기획 추가

- 사업 기획서에 공통 구매비용 비교 요약과 안내서 연결을 추가하고, 서비스 안내서에 `#buying` 목차·설명을 추가했다. 실제 비교 기능이나 외부 데이터 연동은 구현하지 않았다.
- 인앱 브라우저에서 목차를 통해 구매비용 비교 설명으로 이동했고, 1440px에서 가로 넘침이 없는지 확인했다. 기획서의 안내서 연결 링크 1개와 구매비용 요약 표시를 확인했다.
- JavaScript 구문, HTML 중복 ID·로컬 파일 링크·안내서 목차 앵커, `git diff --check`를 확인했다. 실제 상품 가격 정확도·검색 결과·중고 매물 수집·사용자 구매 판단은 이번 검증 범위에 없다.

## 2026-09-30 — 구매부터 관리·인계까지 전체 시안 확장

이번 기록은 앞선 등록·관찰 중심 75개 확인 이후의 별도 검토다. 사용자가 전체 기획과 연결 흐름 보완을 요청해, 모바일 시안과 PC 안내서를 함께 갱신했다. 실제 참가자·거래·전문 상담을 수행한 결과가 아니다.

### 반영 범위

- 다섯 메뉴: 오늘·내 정원·구매 비교·도움·사례. 준비물 예산·입양·경과·정보 카드는 관련 화면에서 이어진다.
- 구매 비교에는 가상 매물 12개, 사례에는 가상 기록 6개를 넣었다. 소포장·개인 잔량 판매·무료 나눔과 상태 공개 식물도 포함했다.
- 입양 확인 → 같은 식물의 관찰 → 도움 준비 → 경과·재문의, 사례 → 내 식물, 판매·분양 카드의 선택 공개를 연결했다. 실제 발행·주문·데이터 전송·영구 저장은 없다.
- 서비스 안내 정본에는 서비스별 대상·입력·단계·결과·예외·운영 책임을 정리했다. 공급자 확인, 범위·가격·답변 시간 제안, 고객 수락, 이행과 경과의 운영 조건도 구분했다.

### 발견해 수정한 문제

1. 경과 재문의 구성의 JavaScript 구문 오류를 수정했다.
2. 하단 사례 메뉴가 이전 식물 ID를 유지하던 문제를 고쳤다.
3. 예산 상세에서 돌아올 때 이전 진입 목적·추가 품목이 재적용되던 문제를 고쳤다.
4. 요청 대상이 없는 경우 선택 중이던 다른 식물로 경과가 연결되던 문제를 고쳤다. 기본 관리 예시는 샘플 식물 ID에 명시적으로 연결했다.
5. 식물을 고른 뒤 빈 선택값으로 바꾸면 화면과 저장 대상이 달라질 수 있어 빈 옵션을 비활성화했다.
6. 비교 항목을 뺀 뒤 비활성 버튼에 초점을 보내던 문제를 고쳤다.
7. 입력한 수량과 계산된 합계가 달라지는 문제를 고쳤다. 유효 수량은 input에서 계산하고, 편집 중 잘못된 수량은 합계 대신 안내한다. 입력 종료 시 유효 수량 복구는 모듈 이벤트 검증으로 확인했다.
8. ‘다른 자재 비교’가 이전 상품 상세를 다시 열던 문제를 고쳤다.
9. 프레임 내부의 서비스 안내 링크가 이동하지 않아 상단 문서 탐색 영역으로 옮겼다. 실제 클릭으로 PC 안내서 이동을 다시 확인했다.

수정한 예산 왕복·수량 계산·대상 연결은 인앱 브라우저에서 다시 확인했다. 도구의 텍스트 선택자 불일치와 기존 탭의 상태 갱신 문제는 새 DOM 확인과 새 인앱 탭으로 복구했으며 제품 오류 개수에 포함하지 않는다.
