# 가상 페르소나 기반 모바일 사용성 검토

문서 갱신일: 2026-09-30 · 첫 검토 기준: `8dde54b` · 대상: 모바일 서비스 시안 `concept.html` · 이 보고서는 PC 열람용

## 결론

이번 시안은 기존 **이름 모를 식물 등록 → 관찰 안내 → 첫 기록·정정**에 구매 비교·준비물 예산·입양 체크·경과 관리·유사 사례·판매·분양 카드·개인 간 자재 소량 구매·나눔·상태 공개형 식물 아웃렛을 연결한다. 아래에 새 흐름을 살펴볼 **확장 가상 과업 4개**를 추가한다. 첫 실제 사용자 검토의 대표 과업은 등록과 첫 관찰로 유지한다.

기존 **10개 가상 페르소나와 75개 명시적 확인 항목은 이번 전체 서비스 확장 전, 등록·관찰 버전의 검토 기록**이다. 당시 등록 취소·첫 기록·정정, 27개 도움 조합과 16개 레이아웃 등을 Codex 인앱 브라우저에서 확인했다. 이 숫자를 새로 추가한 모든 화면의 통과 결과나 실제 참가자 수로 해석하지 않는다.

이번 확장 흐름의 대표 경로와 발견한 오류의 수정 후 동작을 인앱 브라우저에서 확인했다. 실제로 수행한 항목·수정 결과·스크린샷은 [최신 확인 기록](verification.md)을 따른다. 아래 확장 과업의 기대 결과는 검토 기준이며, 실행 완료나 실제 사람의 이해를 뜻하지 않는다.

입력과 기록은 열린 페이지의 메모리에서만 유지하며 새로고침하면 초기화된다. 실제 사진 선택·전송, 구매·결제, 상담 접수·답변, 판매글 게시·공유, 가족 계정·동기화·장기 저장은 제공하지 않는다. **실제 참가자 테스트와 수요 검증은 아직 수행하지 않았다.**

## 전체 서비스 확장의 가상 과업 — 이번 검토

P11~P14는 기존 페르소나의 후속 상황을 넓힌 가상 과업이다. 기존 10개와 합쳐 14개 과업을 문서에 두지만, 14명의 사용자나 완료된 테스트를 뜻하지 않는다. 구매 비교와 공급자 관점의 과업은 첫 실제 사용자 검토를 대체하지 않으며 별도 검토 후보로 둔다.

### P11 · 유진 — 가격과 상태를 함께 보는 식물·아웃렛 구매자

- **상황·연결:** 처음 살 식물을 비교하는 P01, 조건과 예산을 따지는 P04의 구매 전 상황이다. 저렴한 식물의 개체 상태와 추가 관리 부담이 걱정이다.
- **과업:** 신품·개인 분양·상태 공개 식물 예시의 규격·발근·포함 구성·사진 종류를 읽고, 배송비 미확인 매물과 직거래 매물을 비교한다. 질문을 정리한 뒤 가상 수령·입양 체크에서 받은 상태와 모르는 점을 남긴다.
- **기대 결과:** 서로 다른 개체를 같은 상품의 최저가로 순위 매기지 않는다. 판매 호가·확인된 비용·미확인 비용·이동비를 구분하고, 공개 상태를 회복 보증으로 오해하지 않는다. 같은 매물의 입양 체크를 다시 열어도 식물이 중복 생성되지 않으며 취소하면 새 식물이 생기지 않는다.
- **우선 확인:** 배송비 미확인을 0원으로 읽는지, 대표·모주 사진을 받을 개체 사진으로 읽는지, 낮은 가격만 보고 관리 부담을 놓치는지. 실제 판매처·실물 상태·건강·거래 가능성은 검증 대상 밖이다.

### P12 · 지민 — 적게 사고 남은 자재를 나누려는 사람

- **상황·연결:** P04의 보유품 활용을 넓힌 상황이다. 필요한 양은 적고, 이미 가진 화분과 개봉한 자재를 먼저 활용하고 싶다.
- **과업:** 소포장과 다른 용량의 자재를 살펴보고 필요한 수량·보유품을 반영한 준비물 예산을 만든다. 비교 화면을 다녀온 뒤 예산을 다시 확인하고, 남은 자재의 양·단위·개봉·보관 상태·수령 조건을 나눔 카드에 정리한다.
- **기대 결과:** L·kg·개를 임의로 환산하지 않고 보유품 제외와 판매처별 배송 조건을 구분한다. 화면을 왕복해도 입력한 예산 조건이 이어진다. 무료 나눔의 상품 가격 0원과 배송·이동 비용을 구분한다. 보관 상태를 모르면 그대로 표시하며 재사용 안전성을 확정하지 않는다.
- **우선 확인:** 작은 포장의 단가와 실제 지출을 혼동하는지, 묶음 배송을 다른 판매처까지 적용하는지, 보유품 체크를 호환성 보증으로 읽는지. 카드 미리보기는 게시·수령 약속이 아니며 주소·연락처를 요구하지 않는다.

### P13 · 서우 — 작업 뒤의 변화를 정리하고 다시 도움을 구하는 사람

- **상황·연결:** P07의 상태 변화와 P10의 식물별 맥락을 잇는다. 직접 정리한 상담 내용이나 분갈이·자리 이동 계획 뒤에 상태가 나아졌는지 확신하지 못한다.
- **과업:** 대상 식물을 골라 작업과 다음 확인 메모·다시 볼 날짜를 남긴다. 경과를 수정·취소·복원하고 ‘더 걱정돼요’ 또는 ‘모르겠어요’에서 재문의 요약을 확인한다. 유사 사례의 조건과 미확인 결과를 읽고 자신의 식물 관찰로 돌아온다.
- **기대 결과:** 계획·경과·최근 유효 관찰과 요청서가 같은 식물에 연결된다. 취소한 경과가 현재 계획처럼 남지 않으며 식물을 바꾸면 내용이 섞이지 않는다. 날짜는 사용자가 고르고, 직접 작성한 계획을 실제 전문가 답변이나 자동 관리 주기로 표시하지 않는다. 사례 검색 결과가 없어도 초기화할 수 있고 사례의 조건 차이·결과 미확인을 읽을 수 있다.
- **우선 확인:** 식물 A의 사례·경과를 본 뒤 B에서 도움을 요청할 때 대상이 이어지는지, 가상 사례의 시도를 진단·효과 보장으로 받아들이는지. 실제 상담 제공·회복 효과·알림 전송은 검증하지 않는다.

### P14 · 정우 — 판매·분양 전에 알려 줄 정보를 고르는 사람

- **상황·연결:** P02의 기록 정정, P08의 공유 범위, P09의 개인 정보 우려를 잇는다. 다른 사람이 받을 식물에 대해 알려 줄 내용과 개인 기록을 구분하려 한다.
- **과업:** 같은 식물의 최근 유효 관찰을 확인한 뒤 공유 여부를 고른다. 사진 종류·크기·발근·화분 포함·희망 가격 또는 무료 나눔·배송비·수령 조건을 채우고 카드 미리보기에서 돌아와 수정한다.
- **기대 결과:** 관찰·개인 메모·위치는 기본 포함되지 않고 직접 고른 항목만 미리보기에 나온다. 취소한 관찰은 제외된다. 사진 종류를 골라도 실제 사진이 첨부된 것처럼 표현하지 않는다. 판매 호가 미입력·배송비 미확인은 총액 확정으로 바뀌지 않으며 나눔 0원과 배송비를 구분한다.
- **우선 확인:** 미리보기를 발행·전송 완료로 오해하는지, 수정·식물 전환 뒤 이전 식물 정보가 섞이는지. 실제 주소·연락처를 수집하지 않으며 거래 성사·품질·인계 효과는 검증하지 않는다.

## 방법과 해석

- 기존 10개 페르소나와 확장 4개 과업은 요구사항에서 만든 **가상의 상황**이다. 실제 모집한 사용자, 인터뷰 대상, 고객을 대변하는 통계 표본이 아니다. 이름과 상황은 모두 예시다.
- 첫 검토는 두 독립 검토가 코드와 기획 문서에서 문제를 찾고, 주 검토자가 브라우저에서 과업을 수행했다. 등록·관찰 버전과 이번 확장 시안의 동작 확인에는 **Codex 인앱 브라우저**를 사용한다. 검토자와 도구를 실제 사용자 수로 세지 않는다.
- 첫 검토는 390 × 844px를 기본으로 320px·480px와 약 44×44 CSS px 버튼·입력을 확인했다. 추가 검토의 화면 폭과 회귀 확인은 아래 표 및 [최신 확인 기록](verification.md)을 따른다. 이전 검토 결과를 수정된 모든 화면의 통과로 옮겨 쓰지 않는다. 데스크톱 제품의 사용성은 평가하지 않는다.
- 완료 시간을 측정하지 않았고 만족도·SUS 점수·전환율·과업 성공률을 산출하지 않았다. 도구가 클릭한 시간은 사람의 탐색 시간이 아니다.
- **현재 시안의 오류**, **아직 표현하지 않은 흐름**, **실제 사람에게 확인할 가설**을 나눠 기록했다.
- ‘높음’은 해당 과업의 진행 또는 의미를 크게 방해한다는 검토자의 판단이다. 운영 중인 서비스의 장애 등급이나 실제 발생 빈도가 아니다.

### P09 · 소라 — 사진과 개인 정보를 남기지 않고 시작하려는 사람

상황: 식물의 이름을 모르고 집 안 사진을 보내고 싶지 않다. 일단 무엇을 확인할지 알아보려 한다.

과업: 이름과 사진 없이 시작해 첫 관찰을 남기고, 이 정보가 언제까지 남으며 누구에게 전달되는지 설명한다.

- 개선: 이름·장소를 비워도 등록할 수 있고, 계정·사진·연락처를 요구하지 않는다. 입력·기록은 현재 창에서만 유지한다는 안내를 둔다.
- 당시 확인: 빈 이름·장소·재배 방식 모름으로 등록하고 관찰을 남기는 동작을 확인했다.
- 실제 사람에게 확인할 것: 요청 미리보기를 접수로 오해하는가? 새로고침 후 기록이 사라지는 점을 이해하는가? 빈 입력이 허용된다는 표현을 찾는가?

### P10 · 태오 — 여러 재배 방식을 함께 관리하는 사람

상황: 일반 흙 화분과 수경재배, 테라리움, 팔루다리움이 있고, 같은 별명을 쓴 식물이 다른 장소에 있다. 새 식물 하나는 재배 방식도 모른다.

과업: 대상에 맞는 관찰 방법을 보고, 같은 별명의 두 식물을 오가며 각각의 기록·취소·도움 요청 조건이 섞이지 않는지 확인한다.

- 개선: 등록의 재배 방식을 다섯 가지로 나눈다. 식물 이름과 별도의 식물 ID로 관찰을 연결한다. 흙 관찰법은 일반 흙 화분에만 제공한다.
- 당시 확인: 다섯 재배 방식의 안내, 같은 별명·다른 장소 식물의 기록 분리, 식물별 요청 조건 분리와 복원을 인앱 브라우저에서 확인했다.
- 남은 범위: 이 검토는 관찰 UI의 구분이다. 식물·배지·용기·장비별 관리 판단이나 동기화의 정확성 검증이 아니다.

## 첫 검토 기록 — 당시 8가지 페르소나

다음 P01~P08과 U01~U08은 개선 전 시안에서 발견한 문제와 **첫 수정 후의 확인 기록**이다. 아래의 ‘없음·평가 불가’는 당시 상태다. 등록·관찰 개선 결과는 위의 이전 버전 표에, 이번 확장의 실행 결과는 [최신 확인 기록](verification.md)에 구분한다.

### P01 · 민지 — 이름 모를 식물을 처음 받은 사람

상황: 식물 한 개를 선물받았다. 이름과 마지막 물주기 날짜를 모른다. 우선 지금 할 일을 알고 싶다.

과업: `내 정원 → 이름 미상으로 등록 → 오늘 → 흙 상태가 모를 때 확인 방법 찾기`.

- 관찰: 정원에는 고정된 예시 3개뿐이며 등록 버튼이 없다. ‘잘 모르겠어요’는 처음에 “확인 방법을 안내받는 단계로 이어져요”라는 예고만 보여줬다.
- 수정: 일반 흙 화분에 한정한 3단계 관찰 안내와 적용 제외 대상을 표시했다. 정원이 샘플이고 등록은 미지원임을 명시했다.
- 재확인: 관찰 안내가 나타나는 부분 과업은 확인했다. 이름 미상 등록과 실제 첫 기록은 여전히 **평가 불가**다.
- 실제 사람에게 물을 것: 관찰과 급수를 다른 행동으로 이해하는가? 이름을 모른 채 시작할 수 있다는 표현을 찾는가?

### P02 · 준호 — 가족과 여러 화분을 돌보는 사람

상황: 집의 여러 공간에 화분이 있고 가족이 서로 다른 시간에 돌본다. 중복 급수와 잘못 누른 기록이 걱정이다.

과업: `오늘 → 최근 작업자·시각 확인 → 내 관찰 남기기 → 잘못된 기록 취소`.

- 관찰: 관찰 버튼은 피드백 한 줄만 바꾼다. 개체별 작업 이력·시각·담당자·수정·취소가 없다.
- 수정: 화면의 선택을 저장된 기록으로 오해하지 않도록 “예시 선택”과 실제 저장이 아님을 표시했다.
- 재확인: 실제 관리 과업은 **평가 불가**다. 이를 공동관리 사용성 통과로 처리하지 않는다.
- 다음 시안: 기록 종류·식물·시각·담당자를 가진 샘플 타임라인과 한 번의 수정·취소 흐름부터 제공한다. 실제 계정·동기화 구축은 별도다.

### P03 · 수연 — 분갈이와 수형 작업을 고민하는 보유자

상황: 커진 식물의 화분을 바꾸고 싶지만 최근 작업 때문에 지금 진행해도 될지 모르겠다.

과업: `가이드 → 분갈이 준비하기 → 최근 변화·시기 → 사진 상담 → 요청 내용 확인`.

- 관찰: 목표는 ‘화분 바꾸기’인데 결과는 “자르기 전에, 방향부터 함께”와 지지대·유인·가지 정리로 남았다.
- 수정: 수형·분갈이·회복의 안내와 확인 항목을 나눴다. ‘직접 하기’는 준비 내용, 상담·작업 의뢰는 요청 내용으로 표현했다.
- 재확인: 분갈이 선택 후 “지금 분갈이가 필요한지 상담”이 나오고 선택한 조건으로 준비 내용을 확인할 수 있었다.
- 한계: 실제 가이드·전문가·작업 결과·가격은 없다. **요청 준비의 부분 흐름만 확인**했다.

### P04 · 현우 — 빈 화분과 공간을 활용하려는 사람

상황: 기존 화분을 버리지 않고 공간에 맞는 조합을 찾고 싶다. 예산을 바꾸며 다른 관심사도 비교한다.

과업: `우리집에 맞는 조합 → 내 화분 활용 → 예산 → 다른 아이템 → 돌아오기 → 요청서 → 예산 변경`.

- 관찰: 다른 아이템을 다녀오면 목표와 예산이 기본값으로 바뀌었다. 열린 요청서는 예산을 바꿔도 이전 금액을 표시했다. 실제 화분 내부 치수 입력은 없다.
- 수정: 같은 문서를 열어둔 동안 경로별 목표·조건·도움 방식을 유지하고, 열린 요청서를 즉시 갱신했다. 보유 화분의 내경·깊이·배수 구조가 추가로 필요함을 표시했다.
- 재확인: ‘내 화분 활용 / 10만–20만 원 / 구성 맡기기’가 왕복 후 유지됐고, 예산 변경 후 요청서도 ‘5만–10만 원’으로 바뀌었다.
- 한계: **적합한 조합 선택은 평가 불가**다. 내부 치수·모름 선택·실제 두 후보·배송 포함 총액이 필요하다.

### P05 · 은서 — 첫 테라리움 수업을 찾는 사람

상황: 직접 만들기, 공방에서 배우기, 완성품 구매 중 무엇이 맞을지 비교한다.

과업: `작은 정원 만들기 → 공방 수업 방식 선택 → 포함 내용 이해 → 요청서 확인`.

- 관찰: 버튼은 ‘상담받을래요’인데 결과는 클래스였고 요청서에는 모든 분야가 ‘상담·클래스’로 섞여 표시됐다.
- 수정: 테라리움에서 ‘직접 만들기 / 공방에서 배우기 / 완성품 의뢰’를 사용하고 요청서에도 같은 표현을 쓴다.
- 재확인: 공방 방식과 요청서가 ‘공방에서 배우기’로 일치했다.
- 한계: **실제 수업 선택은 평가 불가**다. 지역·일정·소요 시간·포함 재료·가격·사후 문의 범위가 없다.

### P06 · 지호 — 이미 만든 테라리움을 관리하는 사람

상황: 기존 용기에 결로가 생겼다. 새 작품 구매보다 현재 용기의 상태 확인이 목적이다.

과업: `내 정원 → 보유 테라리움 → 결로·환기 상태 확인`.

- 관찰: ‘제작·관리 방법 보기’를 누르면 새 작품의 목표 모습·제작 경험·예산을 묻는 화면으로 갔다.
- 수정: 버튼을 ‘새 작품 제작 방법 보기’로 바꾸고 용기별 관리는 준비 중임을 표시했다. 제공하지 않는 관리를 약속하지 않게 했다.
- 재확인: 잘못된 기대를 만드는 이름은 수정했다. **용기 관리 자체는 여전히 평가 불가**다.
- 다음 시안: 일반 화분 물주기와 구분되는 용기 유형·결로·수위·장비 점검의 대표 화면이 필요하다.

### P07 · 다은 — 식물 상태 변화로 걱정하는 사람

상황: 잎 상태가 달라져 원인과 다음 확인 항목을 알고 싶다. 잘라내는 작업은 결정하지 않았다.

과업: `내 식물 가꾸기 → 건강하게 회복 → 사진 상담 → 준비할 정보 확인`.

- 관찰: 회복을 골라도 수형·가지 정리 상담이 그대로 나왔다.
- 수정: 전체·변한 부위·잎 뒷면 사진, 시작 시점, 최근 관리 변화와 경과 확인으로 안내를 바꿨다. 원인을 확정하지 않는다.
- 재확인: “관찰 기록을 모아 회복 방향 상담”과 해당 확인 항목이 나타났다.
- 한계: **진단·상담·회복 효과는 검증하지 않았다**. 사진 업로드·이력 연결·상담 제공이 필요하다.

### P08 · 영숙 — 작은 화면에서 위치와 공유 범위를 확인하려는 사람

상황: 긴 화면을 오가며 방금 선택한 내용이 무엇인지 확인하고 싶다. 집 사진이 바로 전달되는지도 걱정이다.

과업: `화면 하단 → 내 정원 → 선택 식물에서 조합 검토 → 미리보기 → 조건 수정`.

- 관찰: 메뉴 이동 후 제목 위치가 화면 위로 약 298px 벗어나 있었다. 스킨답서스 카드에서 들어가도 대상이 빈 공간 예시로 바뀌었다. 요청서를 열어도 초점이 이전 버튼에 남았다.
- 수정: 메뉴를 이동하면 시작 위치와 제목으로 초점을 옮긴다. 정원의 스킨답서스를 조합 검토 대상으로 유지한다. 요청서 제목으로 초점을 옮기고 조건 수정으로 돌아갈 수 있게 했다.
- 재확인: 제목이 화면 안에 있고 활성 초점이 제목으로 이동했다. 선택한 식물과 재배치 목표도 이어졌다.
- 한계: 이 점검은 **스크린리더 사용성 통과나 실제 고령자 평가가 아니다**. 당시 공유 항목 선택·전송 화면도 미지원이었다. 이번 카드의 포함 항목 선택은 P14에서 검토하며 실제 전송은 제공하지 않는다.

## 다음 검토의 우선순위

### 우선 1 · 첫 관찰 경험을 실제 초보자와 확인

첫 과업은 `이름 미상 등록 → 모름 선택 → 관찰 안내 → 첫 관찰 → 기록 다시 찾기`로 유지한다. 초보 지인 후보 2~3명에게 공유 시안과 안내문 준비 후 2026-09-30 기준 이번 주에 참여를 부탁할 계획이다. 혼자 휴대전화로 체험한 뒤 메신저 질문 5개에 답하는 방식이며 비용은 0원이다. 아직 참가자 수락이나 과업 결과는 없다.

다음 방문에 기록을 이어 쓰는 기능은 없다. 20명·4주 관리 실험은 기록 지속성과 제공 범위가 준비된 뒤 검토할 후속 제안이다. 현재 시안 과업 완료를 장기 재사용이나 관리 효과로 바꾸어 해석하지 않는다.

### 우선 2 · 전체 서비스 확장의 동작과 이해 확인

P11~P14를 기준으로 구매 비교·예산·입양·경과·사례·판매·나눔 카드 사이의 대상과 입력 유지, 미확인 비용, 취소와 되돌리기, 실제 전송 여부의 표현을 검토한다. 인앱 브라우저 실행 결과는 [확인 기록](verification.md)에 남긴다. 이후 실제 사람에게 추가 과업을 제시할 때에도 첫 관찰 과업과 결과를 구분한다.

가상 매물을 고르는 행동은 실제 구매 의사가 아니다. 어떤 조건과 비용을 이해했는지, 무엇을 몰라 선택을 보류했는지 설명을 확인한다. 실제 판매처 정보의 정확성·거래·검수·물류·분쟁 대응은 별도 운영 검증이 필요하다.

### 후속 · 유료 도움·규격 적합성·운영 범위

- **전문가 제안 비교:** 수형·분갈이 한 문제의 제공 범위·가격·답변 시점·후속 문의·운반·취소 조건을 준비한 뒤 선택 이유를 검토한다. 현재 요청 준비와 경과 메모가 실제 전문가의 답변이나 유료 서비스 제공을 뜻하지 않는다.
- **공간·보유 화분의 적합성:** 가상 예산의 수량·보유품 제외와 실제 호환성을 구분한다. 내경·깊이·배수 구조·모름과 생육 조건을 확인할 범위는 별도로 준비한다. 사진이나 보유품 체크만으로 치수와 적합성을 확정하지 않는다.
- **용기 관리·공방 운영:** 제작 예약과 기존 작품 관리를 나눠 검토한다. 바깥 관찰과 가상 사례를 구성별 전문 관리법으로 해석하지 않는다. 공방의 날짜·지역·인원·포함 재료·사후 문의 범위는 고객용 시안만으로 평가할 수 없다.
- **공동관리·실제 공유:** 카드의 선택 항목 미리보기 다음 단계에서 동의·공유·회수 범위를 검토한다. 여러 담당자의 동시 기록·가족 초대·기기 간 동기화·여행 기간 종료는 별도 과업이다.

## 첫 실제 사용자 검토의 진행안

**선택한 계획:** 초보 지인 후보 2~3명, 혼자 휴대전화로 체험, 체험 후 메신저 질문 5개, 비용 0원. 공유할 시안과 안내문이 준비되면 2026-09-30 기준 이번 주에 참여를 부탁한다. 이는 참여 확정이나 일정 확약이 아니며 실제 요청·수락·응답 수와 진행일은 따로 기록한다. 이전의 5~8명 제안은 확정 모집 수가 아니다.

참가자에게 제시할 대표 과업:

> 이름과 물 준 날을 모르는 식물을 받았습니다. 지금 확인할 것을 찾아 첫 기록을 남겨 주세요.

실제 개인 사진 없이 같은 과업을 제시한다. 버튼 위치와 클릭 순서를 먼저 알려주지 않는다. 직접 관찰은 필수로 두지 않으며, 참가자가 혼자 체험한 뒤 아래 같은 질문에 답한다. 완료하지 못했거나 해보지 않은 항목도 그대로 받는다.

| 과업 후 메신저 질문 초안 | 해석 범위 |
|---|---|
| 어디까지 진행했나요? 막힌 곳이 있다면 알려 주세요. | 참여자가 보고한 완료 범위와 막힌 위치 |
| 이 화면에서 기록한 것은 어떤 뜻이라고 이해했나요? | 관찰과 실제 관리 작업을 구분하는지에 대한 설명 |
| 방금 남긴 기록은 어디에서 다시 찾았나요? | 대상·내용을 다시 확인했다는 자기보고 |
| 내용을 고치거나 메뉴를 옮겨 보았다면 어땠나요? 해보지 않았다면 그렇게 알려 주세요. | 정정·이동 경험. 미시도는 실패와 구분 |
| 새로고침하면 기록은 어떻게 될까요? 요청 미리보기가 실제 상담 접수라고 생각했나요? | 저장 지속성과 전송 여부에 대한 이해 |

**과업 후 자기보고를 실제 클릭 순서·정확한 소요 시간·도움 없이 완료했다는 직접 관찰 결과로 세지 않는다.** 후보·요청·수락·응답 수와 미확인 부분을 구분한다. 기능이 없는 곳은 참가자 실패로 세지 않는다. 가상 제안 선택, 지불 의향 발언, 실제 결제·이용도 서로 다른 근거다.

구매 비교·아웃렛·자재 나눔·경과·분양 과업은 별도 추가 검토 후보다. 이번 첫 과업에 모두 얹거나 아직 하지 않은 실제 사용자 검토를 완료한 것으로 기록하지 않는다.

## 관찰 안내의 근거

- [메릴랜드대학교 — Watering Indoor Plants](https://www.extension.umd.edu/resource/watering-indoor-plants): 흙의 촉감과 화분 무게를 살펴보는 방법. 실내식물의 물 요구량이 조건에 따라 다름.
- [아이오와주립대학교 — How to Care for Houseplants](https://yardandgarden.extension.iastate.edu/how-to/how-care-houseplants): 식물·배지·화분·환경을 고려하는 관리 설명.

위 자료를 참고해 일반 흙 화분의 **관찰** 문구를 작성했다. 수경재배·밀폐 테라리움·팔루다리움을 적용 대상에서 제외한 것은 제품 범위를 정하기 위한 설계 판단이다. 이 문구가 특정 식물의 급수 필요나 진단을 확정하지 않는다.
