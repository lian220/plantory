# 고객 시나리오와 사업 연결

작성: 2026-09-29 · 갱신: 2026-09-30. 다음 내용은 가상 상황을 바탕으로 한 서비스 가설이며 실제 사용자 테스트·상담·거래 결과가 아니다. 모든 흐름은 모바일 기준이다.

일상 관리, 수형·분갈이, 공간·화분 선택, 테라리움의 네 영역을 유지한다. 첫 검토는 지인 초보자가 비용 없이 모바일 시안을 사용하는 방식이며, 아래 A의 첫 등록·관찰·기록 확인 과업부터 시작한다. 전체 제공 범위와 화면별 역할은 [서비스 안내서](service-guide.md)에 있다.

## 공통 구조

고객의 현재 상황 → 원하는 변화 → 방법·상품·사람 중 필요한 도움 → 조건·견적 확인 → 실행 → 경과 기록.

관찰과 작업을 구분한다. ‘흙이 젖어 있음’은 관찰이며 ‘물을 줌’은 작업이다. 사진·관리기록은 선택한 목적과 범위로만 공유한다. 매칭은 요청자가 조건과 비용을 확인한 뒤 선택하는 과정이다.

## A. 새 식물의 이름과 관리법을 모른다

- **계기:** 구매·선물 직후 어디에 두고 어떻게 돌볼지 궁금하다.
- **현재 대안:** 판매 라벨, 가게 문의, 검색, 식물 인식 앱.
- **첫 시안 과업:** 선물받은 식물 → 내 정원에서 등록 → 일반 흙 화분·이름 모름·장소 → 오늘의 모름 선택 → 관찰 방법 확인 → 첫 관찰 기록 → 같은 식물의 기록 확인 → 필요 시 수정·취소.
- **이후 서비스 흐름:** 선택한 전체·잎 사진 → 식물 후보 확인 또는 이름 직접 입력·이름 미상 → 놓을 공간 → 마지막 물주기는 모름 허용 → 확인할 항목 안내 → 관찰·작업 기록.
- **핵심 가치:** 등록하기 쉽고 현재 무엇을 확인해야 하는지 이해한다.
- **수익 연결 가설:** 기본 관리는 유입·유지 기반. 이 과정만으로 구독 수요가 있다고 가정하지 않는다.
- **추가 아이디어:** 구매처 QR로 알려진 이름·구매일·관리 정보를 가져온다.
- **확인:** 사진 인식 실패나 이름 미상 때문에 등록이 막히지 않는가? 실제 다음 관찰로 돌아오는가?
- **현재 한계:** 첫 시안에서는 사진과 계정을 요구하지 않는다. 기록은 열린 페이지 안에서만 사용하며 새로고침 후 유지되지 않는다. 장기 이용이나 실제 관리 효과는 별도 검증한다.

## B. 화분이 많아 가족과 관리가 겹친다

- **계기:** 장소별로 관리 상태가 다르고 누가 물을 줬는지 기억하기 어렵다.
- **현재 대안:** 기억, 메모, 가족 메시지, 기존 관리 앱.
- **흐름:** 공간별 목록 → 확인 필요·예정·완료 → 관찰 → 작업자·시각 기록 → 수정·취소 → 다음 확인 조정.
- **핵심 가치:** 중복 작업과 기록 부담을 줄인다.
- **수익 연결 가설:** 장기 기록·센서 통합 등 추가 가치가 구독 이유가 되는지 별도 확인한다.
- **추가 아이디어:** 오랜만에 돌아와도 과거 알림을 모두 실행시키지 않는 복귀 흐름.
- **확인:** 가족의 실제 계정·초대·철회·기기 간 기록 확인이 필요한가? 단순 이름 선택으로 공동관리를 대체하지 않는다.

## C. 우리집에 맞는 식물과 화분을 고르고 싶다

- **계기:** 빈 공간, 이사, 인테리어 변화, 선물.
- **현재 대안:** 핀터레스트·SNS, 쇼핑몰, 식물가게 상담.
- **흐름:** 공간 사진·치수 → 빛·관리 시간·취향·예산 → 생육 조건과 스타일을 따로 설명 → 식물·속화분·겉화분 비교 → 비용 확인 → 구매 후 관리 등록.
- **핵심 가치:** 보기 좋은 조합을 실제 크기·환경·비용과 연결한다.
- **수익 연결 가설:** 상품 구매 수수료, 구체적인 공간 상담, 제휴 스타일링.
- **추가 아이디어:** 보유 식물·빈 화분 우선 활용, 이사 후 재배치.
- **확인:** 클릭이 아닌 구체적인 구매 의사·구매 완료가 생기는가? 사진만으로 광량·실측 치수를 확정하지 않는다.

## D. 기존 식물을 원하는 수형으로 가꾸고 싶다

- **계기:** 너무 크거나 한쪽으로 퍼졌거나, 원하는 모양으로 키우고 싶다.
- **현재 대안:** 영상·카페 질문·판매자 조언·가까운 가게 방문.
- **흐름:** 정면·측면·줄기 사진 → 원하는 수형 → 최근 분갈이·손상·생육 상태 → 적용 가능한 방법 비교 → 직접 하기/상담/작업 의뢰 → 작업 이력 → 새순·형태 변화 사진.
- **핵심 가치:** 손대기 어려운 결정을 구체적인 행동과 도움으로 바꾼다.
- **수익 연결 가설:** 건별 상담, 작업 매칭, 지지대·화분·용토 등 상품 연결.
- **추가 아이디어:** 목표 수형 보드, 잘라낸 가지의 삽목 기록과 모체 연결.
- **확인:** 정보를 보고도 전문가에게 비용을 내는 상황이 있는가? 전문가 시간이 수수료보다 커지지 않는가?
- **범위:** 초기에는 검토한 식물별 가이드·도해. 사진 위 절단 위치 확정이나 완성 수형·기간 보장은 하지 않는다.

## E. 잎이나 생육 상태가 갑자기 달라졌다

- **계기:** 황변·처짐·성장 정체 등 관찰 변화.
- **흐름:** 증상 사진·시점 → 최근 물주기·분갈이·비료·위치 변경 기록 → 사실·가능성·추가 확인 분리 → 관찰 추가 → 필요 시 SOS 카드로 상담.
- **핵심 가치:** 상담할 때 상황을 반복 설명하는 부담을 줄인다.
- **수익 연결 가설:** 전문 상담·현장 점검 연결. 일반 챗봇 상담과의 차이를 확인한다.
- **추가 아이디어:** 지켜보는 중·해결됨·악화됨으로 상담 후 실제 경과를 남긴다.
- **확인:** 정확한 자동 진단을 약속하지 않는다. 조경기사 자격이 모든 식물의 병해 진단·전정 전문성을 보장한다고 표현하지 않는다.

## F. 테라리움·팔루다리움을 만들고 싶다

- **계기:** 참고 작품을 보고 제작·수업·주문을 고민한다.
- **흐름:** 취향 사진·용기 크기·예산·경험 → 레시피·준비물/공방·클래스/완성품 의뢰 → 구성·견적 확인 → 제작 → 용기 단위 관리 등록.
- **핵심 가치:** 작품 사진과 실제 제작 가능성을 연결한다.
- **수익 연결 가설:** 공방 매칭·재료 구매 연결, 반복 요청을 바탕으로 자체 키트 검토.
- **추가 아이디어:** 수업 QR로 구성품과 관리법 등록, 경험자 레시피와 결과 비교.
- **관리:** 식물·배지·조명·장비·제작일, 결로·환기·수분·수위 등 용기별 항목. 동물 사육·질병 안내는 별도 분야로 제외한다.
- **확인:** 레시피를 원하는지, 수업·완성품을 원하는지 구분한다. 배송 파손·생물 상태·재료 교체·원가를 확인한다.

## G. 여행·선물·분양으로 돌봄을 넘긴다

- **계기:** 부재 기간 또는 소유자 변경.
- **흐름:** 기간·대상 선택 → 공유 항목 확인 → 담당자 작업 → 기간 종료 시 접근 종료. 선물은 새 환경 확인 후 새 관리 기준 설정.
- **핵심 가치:** 필요한 정보만 전달하고 관리가 이어진다.
- **수익 연결 가설:** 초기에는 기존 고객 편의. 유료 방문 돌봄은 공급·신뢰·운영을 검증한 뒤 별도 검토.
- **추가 아이디어:** 식물 여권에 이름·선택한 성장기록·관리법을 담아 전달.
- **확인:** 집 사진·개인 메모·센서 위치가 자동 공개되지 않는가? 이전 집의 물주기 간격을 새 집에 그대로 적용하지 않는가?

## 매칭 요청서의 최소 내용

대상과 현재 상황, 원하는 변화, 선택한 사진, 도움 방식, 시기, 예산 범위, 방문이 필요할 때만 지역·운반 조건. 견적 수락 전에는 불필요한 집 주소·연락처·개인 기록을 공급자에게 전달하지 않는다.

현재 시안은 요청 내용을 미리 보는 단계이며 실제 전송·전문가 답변·예약·결제가 없다. 초기 운영은 전국 온라인을 기준으로 준비하고, 방문·운반·공방 수업은 파트너 확보 후 제공 가능 여부를 확인한다. 창업자는 기획·운영을 맡고 전문 안내는 전문가 협업으로 검토한다. 현재 파트너는 확보되지 않았다.

## 검토와 비교 실험의 순서

먼저 A의 대표 과업으로 이름 미상 등록, 관찰과 급수 구분, 첫 기록 확인이 가능한지 관찰한다. 참여 인원·일정은 미정이며 실제 참가자 검토 결과는 아직 없다.

후속으로 **기존 식물 가꾸기 / 공간·화분 / 테라리움 제작** 세 문제를 같은 기준으로 비교한다. 식물 수·취미 경력 자체보다 최근 실제 사건, 기존 대안, 지출·시간, 유효 요청, 제안 수락, 이용 완료를 본다. 정원 관리의 장기 사용성과 건별 매칭의 사업성은 별도 지표로 평가한다.
