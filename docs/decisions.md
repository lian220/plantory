# 결정과 미결정

작성: 2026-09-29 · 갱신: 2026-09-30. 사용자의 사업기획 의도와 후속 답변을 기준으로 정리한다.

## 확정한 방향

1. 지금의 ‘설계’는 비즈니스 아이템과 서비스 기획이다. 최신 요청은 추가 질문 없이 전체 서비스와 추가 기능을 설계하고 모바일 시안 완성도를 높이는 것이다. 실제 운영 서버 구축은 포함하지 않는다.
2. 개인 식물 관리가 서비스의 기반이다. 초보자, 여러 화분을 키우는 사용자, 테라리움·팔루다리움 사용자를 고려한다.
3. 사진 식별, 집 환경·인테리어 적합성, 화분 매칭, 수형·분갈이 가이드를 검토 대상에 포함한다.
4. 첫 목표는 사람이 모바일 시안을 사용해 보는 것이다. 이후 첫 서비스 운영은 매칭 중심으로 검증하고, 직접 상담·키트 판매·클래스는 후속으로 검토한다.
5. 앱 기록과 기존 센서 연동을 검토하되 자동 급수는 이후 연구한다.
6. **실제 서비스와 서비스 시안만 모바일 전용**이다. `concept.html`은 넓은 화면에서도 같은 모바일 구성을 보여주며 PC용 서비스 제품은 만들지 않는다. 사업기획서·서비스 안내서·사용성 보고서 등 내부 문서는 **PC에서 읽기 편한 구성**으로 작성한다.
7. 프로젝트 작업명은 `plantory`, 기획 정본 위치는 저장소의 `docs/`, GitHub는 `lian220/plantory` 비공개다. 개인 컴퓨터의 절대 경로를 프로젝트 기준으로 사용하지 않는다.
8. 저장소 산출물은 사업기획 문서와 시각화·탐색 시안이다. 이번 개선에 백엔드·API·인증·결제·사진 전송·영구 저장·공개 배포는 포함하지 않는다. 커밋·push는 별도 승인 범위에 따른다.
9. 일상 관리, 수형·분갈이, 공간·화분 선택, 테라리움의 네 영역을 유지한다. 첫 시안 과업은 초보자의 일상 관리부터 확인한다.
10. 첫 참가자는 지인 중 식물 초보자로 모집하며 별도 비용을 쓰지 않는다. 초보 지인 2~3명을 후보로 두고, 혼자 시안을 사용한 뒤 메신저로 같은 질문 5개에 답변받는다. 공유할 시안과 안내문이 준비되면 이번 주(2026-09-30 대화 기준)에 부탁할 계획이다. 실제 참여 수락·실행 날짜·공유 방식은 아직 확정하지 않았다.
11. 대표 과업은 ‘선물받은 식물 등록(이름 모름 허용) → 모름 선택과 관찰 안내 → 첫 기록 → 같은 식물의 기록 확인’이다.
12. 창업자는 기획·운영을 맡고 전문 안내는 전문가 협업으로 준비한다. 현재 확보된 전문가·공방 파트너는 없다.
13. 초기 운영 범위는 전국 온라인이며, 투입 가능한 시간은 주당 16시간 이상이다. 실제 상담 분야·인원·응답 시간은 공급을 확인한 뒤 정한다.
14. 사용자가 요청한 **식물·원예자재 구매비용 비교와 신품·중고 함께 확인**을 기획에 포함한다. 네 영역에서 함께 쓰는 공통 기능으로 정리하며, 구체적인 흐름·품목·비교 조건·표시 항목은 아래 설계안으로 구분한다.

15. 구매비용 비교와 함께 목적별 준비물·총예산, 보유 물품·규격 확인, 중고 구매 확인표, 조건에 맞는 매물·가격 알림, 구매 내역과 관리 연결을 **기획 검토 범위에 포함**한다. 사용자의 추가 반영 의사를 기록하며, 실제 출시·운영 조건은 미정이다. 이번 개선 시안의 범위는 아래 종합 설계 결정에 따른다.
16. 후속 선택 질문에서 **새 식물 입양 체크, 상담·분갈이 후 경과 관리, 내 환경과 비슷한 관리 사례 찾기, 판매·분양 정보 카드**를 기획에 포함하기로 정했다. 이후 종합 요청으로 네 흐름을 이번 개선 시안에 연결한다. 실제 출시·운영 조건은 따로 정한다.

### 종합 요청에 따른 설계 결정 — 2026-09-30

사용자는 추가 질문을 멈추고 추가 서비스까지 전체 기획과 모바일 시안의 완성도를 높이도록 맡겼다. 아래는 그 요청에 따른 **설계 판단**이며, 개별 선택 답변이나 시장에서 검증된 수요로 기록하지 않는다.

- **전체 흐름:** 구매 비교 → 조건·총액 → 가상 수령 → 입양 체크 → 같은 식물 등록·관찰 → 도움 요청 미리보기 → 개인 경과 계획 → 재문의 준비.
- **다섯 메뉴:** 오늘 / 내 정원 / 구매 비교 / 도움 / 사례. 기존 가이드는 도움에 통합한다.
- **함께 연결:** 내 정원 → 판매·분양 카드 미리보기, 사례 → 관찰·도움, 도움 → 분갈이·테라리움 준비물 예산 → 구매 비교.
- **이번 개선 시안:** 가상 상품·매물, 동일 규격과 식물 조건 대안, 배송 미확인 표시, 보유품 제외, 판매처별 배송 합계, 소포장 비교, 가상 사례·입양·개인 경과·정보 카드.
- **추가 선택과 설계 채택:** 소포장과 개인 원예자재 잔량 구매·나눔을 함께 다루는 B안은 사용자가 직접 선택했다. 상태 공개형 식물 아웃렛은 종합 요청에 따른 설계 판단이다. 예시 탐색·조건/질문 정리·카드 미리보기는 시안에 연결하고, 실제 거래·검수·물류는 공급·상태·수령·책임 검토 뒤 운영한다.
- **운영 준비 후:** 실제 가격·매물·구매 이력·알림·전문가 제안과 응답. 자체 게시판은 사례와 운영 여력이 확보된 뒤 검토한다.
- **체험 범위:** 가상 데이터와 현재 창 메모리만 사용한다. 외부 전송·상담·결제·실시간 시세·사진 업로드·영구 저장을 수행하지 않는다. 개인 경과 계획은 전문가 안내나 무료 재상담 약속이 아니다.
- **현재 우선순위:** 기획과 연결 시안 완성. 초보 지인 후보 2~3명·혼자 사용 후 메신저 질문 다섯 개·자료 준비 후 이번 주 요청이라는 외부 검토 계획은 유지한다. 실행·참가자 확정·배포로 간주하지 않는다.

### 구매비용 비교의 요구와 설계 제안 — 2026-09-30

- **확정 요구:** 판매처별 가격 차이로 불편한 식물·원예자재의 구매비용을 비교하고 신품과 중고를 함께 확인한다.
- **흐름 설계안:** `검색 → 비교 조건 설정 → 신품·중고 비교 → 총액·상태 확인 → 판매처 이동 → 구입 후 내 식물 등록`을 네 서비스 영역에 연결한다. 원예자재·장비는 해당 식물의 준비물·관리 이력에 연결하는 방향이다.
- **설계 제안:** 식물은 품종·크기·발근/삽수·상태·화분 포함 여부를 맞춰 비교한다. 자재·장비는 같은 모델·규격과 L/kg/개 등 같은 단위의 가격을 보여준다. 동일 상품과 유사 조건의 대안은 나누어 표시한다.
- **표시 설계안:** 배송·필수 옵션을 포함한 구매 총액, 출처·확인 시각·미확인 정보·지역 직거래를 구분한다. 식물의 신규 판매와 개인 분양을 일괄 ‘중고’로 묶지 않고 판매 유형과 생물 상태를 표시한다. 공개 매물 가격은 판매자의 호가이며 확인되지 않은 실제 거래가로 표현하지 않는다. 배송비를 모르면 0원으로 계산하지 않는다.
- **기획과 구현 구분:** 이번 개선 시안은 가상 상품을 비교하고 가상 수령으로 이어진다. 실제 가격·재고·판매처 구매는 제공하지 않는다. 첫 초보자 관찰 과업은 유지하고, 구매 비교 사용성은 추가 검토 후보로 둔다.
- **연동 미정:** 다나와·네이버 가격 비교 경험은 참고 대상으로 삼고, 네이버·당근·번개장터·중고나라 등은 데이터 출처 후보로 검토한다. 자동 통합·API·수집·제휴 가능성을 확정하지 않는다.
- **기획에 포함한 후보:** 목적별 준비물 총예산, 보유품·규격 확인, 중고 구매 확인표, 조건에 맞는 가격 알림, 구매 내역과 관리 연결. 전체 준비물 예산에서는 필수·선택 품목과 판매처별 배송비를 구분하는 설계안을 검토한다. 이번 시안 범위는 위 종합 설계 결정에 따르고 실제 데이터·운영 조건은 미정이다.
- **우선순위:** 가상 총예산·보유품·입양 확인을 이번 개선 시안에 연결하고 실제 알림·구매 내역 연동은 후속으로 살펴본다. 검수·거래 중개와 공동구매는 별도 제안이며 수요·데이터·운영 부담을 확인한 뒤 결정한다.

### 커뮤니티 조사 후 제안과 사용자 선택 — 2026-09-30

국내 3개·해외 5개 공개 글의 본문과 공식 사이트 2곳의 설명을 확인했다. 사용자가 요청한 다각도 분석이며, 실제 고객 인터뷰나 서비스 이용 검증은 아니다. 출처와 확인 범위는 [조사·검증 문서 8절](research-and-validation.md#community-review)에 기록한다.

- **기획 포함 — 새 식물 입양 체크:** 구입·선물·분양으로 식물을 받았을 때 설명과 실제 상태를 확인하고, 질문·첫 관찰을 내 식물 관리에 연결한다. 기존 구매·수령 확인 카드를 구체화한 방향이다.
- **기획 포함 — 상담·분갈이 후 경과 관리:** 안내받은 확인 항목·재확인 시점·이후 변화를 정리해 필요할 때 재문의 자료로 쓴다. 전문가의 지속 관찰이나 무료 재상담 범위는 정하지 않았다.
- **기획 포함 — 내 환경과 비슷한 관리 사례 찾기:** 식물·빛·재배 방식·증상에 따라 사례를 찾아 시도한 방법과 이후 결과를 함께 본다. 공개 범위·자료 확보·검토 방식은 별도 설계한다.
- **기획 포함 — 판매·분양 정보 카드:** 판매자·분양자가 개체 사진·크기·상태·구성·수령 조건·관리 이력을 정리해 구매 비교와 인수 후 관리에 활용한다.
- **추가 결정:** 소포장 비교·보유품 활용과 개인 자재 잔량 구매·나눔(B안)은 사용자 선택이다. 아웃렛은 종합 설계로 채택했다. 예시 탐색·조건 정리·미리보기는 이번 시안, 실제 거래·검수·물류는 후속 운영이다. 기록 공백 복귀·보유 부담에 따른 인계는 추가로 다듬는다.
- **미결정:** 실제 공급·자료·상담 가격·응답·거래 책임·운영 방식. 자체 커뮤니티 게시판은 답변자·운영 여력과 이용 이유를 확인한 뒤 검토하는 것을 제안한다.
- **기존 결정 유지:** 첫 초보자 등록·관찰 과업은 유지한다. 실제 구매 비교 사례, 판매자·전문가 참여, 운영 시간과 유료 수요는 별도로 검증한다.

### 문서와 서비스 화면의 기준 — 2026-09-30 정정

사용자 정정에 따라 ‘서비스와 기획 화면 모두 모바일’이라는 기존 기준을 변경한다. `index.html`, `service-guide.html`, `usability.html`은 내부 검토 문서이므로 PC에서 본문·표·목차·캡처를 읽기 쉽게 구성한다. 모바일 폭을 유지하는 대상은 실제 서비스와 `concept.html` 시안이다. 서비스 기능·사업 가설·검증 순서는 이 구분 때문에 바뀌지 않는다.

## 확인된 진행 상태

- 페르소나 검토는 가상 인물과 과업을 이용한 시안 점검이다. 실제 고객 조사 결과가 아니다.
- 실제 참가자 모집·사용자 테스트·유료 수요·전문가 계약은 아직 확인하지 못했다.
- 시안의 비교·등록·관찰·계획·카드는 가상 데이터와 현재 열린 페이지에서만 쓰는 체험이다. 재방문·장기 기록·공동관리는 별도 검증이 필요하다.
- 개선 시안의 구체적인 구현 확인 결과는 [확인 기록](verification.md)에 남긴다. 서비스 구성과 흐름은 [서비스 안내서](service-guide.md)를 기준으로 한다.

## 우선 검증할 가설

- 기존 식물의 수형·분갈이 문제는 방법·상품·전문가 매칭으로 연결할 수 있다.
- 공간·화분 매칭은 구매 결정을 돕지만 추천이 실제 구매로 이어지는지 검증해야 한다.
- 테라리움 제작 매칭에서 반복되는 요청을 파악하면 향후 자체 키트 구성을 결정할 수 있다.
- 개인 관리기록은 반복 이용의 기반이 될 수 있으나 구독 결제 이유가 되는지는 별도 검증한다.
- 식물가게·공방 연계는 고객 유입 통로가 될 수 있지만 제휴처의 참여와 비용 지불은 미확인이다.
- 조건과 구매 총액을 맞춘 신품·중고 비교가 탐색 시간을 줄이고 구입 후 관리로 이어지는지 검증한다. 최저가 클릭이나 외부 판매처 이동만으로 구매 완료를 판단하지 않는다.

## 아직 확정하지 않은 것

최종 브랜드명, 시장 규모, 상담 가격, 매칭 수수료, 회원 구독료, 제휴 계약, 자체 키트 구성, 자동 식물 진단 정확도, 수형 예측 정확도, 사업지원 선정 가능성은 확정하지 않았다. 시각 기획서의 수익 계산 숫자는 계산 구조를 설명하는 **가정 예시**다.

## 기존 작업과의 관계

로뚜의 ‘기록→발견→다음 행동’, 사용자가 해석을 고칠 수 있는 흐름은 참고한다. 로뚜 코드·개인 데이터는 가져오지 않았다. 이전 대화에서 만든 비공개 Sites 등록·프레임워크 스캐폴드는 이 사업기획 저장소와 별개다. 현재 웹 배포는 없다.
